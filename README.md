# eCore

Своё ядро векторной анимации для веба. Играет анимированные стикеры и эмодзи Telegram, хранит их в файлах
вдвое меньше `.tgs` и меняет цвета и положение деталей без пересборки сцены.

**Посмотреть вживую:** https://tier.guru/ecore/

Бесплатно при одном условии: в интерфейсе продукта видна надпись **Rendered with eCore** со ссылкой.
Подробности в разделе [Лицензия](#лицензия).

## Зачем оно

- **Файлы вдвое меньше.** `.ecr` занимает около 54% от того же `.tgs`.
- **Картинка как в Telegram.** Ядро сверено с rlottie, движком самого Telegram, кадр в кадр.
- **Одинаково на любом устройстве.** Плеер сам сверяет кадры видеокарты с расчётом на процессоре и, если видеокарта ошиблась, переходит на Canvas 2D.
- **Правка без задержки.** Перекрасить заливку или сдвинуть слой можно на лету, сцена не пересоздаётся.
- **Работает без браузера.** Тот же плеер рисует кадры на сервере: превью для бота, проверка шаблонов.
- **Один файл.** Плеер занимает 32 КБ в gzip, без wasm и без зависимостей. Весь код в `src/` написан с нуля.

## Из чего состоит

1. **Плеер** `src/ecore.js` играет файлы `.ecr`. Рисует тремя способами: видеокартой (WebGL2), через Canvas 2D
   и на процессоре без браузера. Первый кадр появляется сразу, видеокарта подключается в фоне.
2. **Формат `.ecr`** и упаковщик `src/ecr.js`: компактная бинарная сцена со своим сжатием.
   Получается из готового `.tgs` или из исходника.
3. **Исходник** и компилятор `src/source.js`: обычный SVG с CSS-анимацией, в котором текст остаётся текстом.
   Из него собираются `.ecr` для плеера и `.tgs` для Telegram. Правила формата описаны в [SPEC.md](SPEC.md).

## Быстрый старт

### На странице

```html
<script src="ecore.js"></script>
<e-core src="sticker.ecr" style="width:160px"></e-core>
```

Атрибуты тега: `src`, `still` (стоп-кадр, который показывается раньше анимации), `loop`, `autoplay`, `speed`,
`size`, `backend` (`gl`, `2d` или `soft`), `subframe`.

### Из кода

```js
const anim = ECore.mount(element, 'sticker.ecr', { loop: true, autoplay: true });
anim.pause(); anim.play(); anim.seek(30);
anim.setSource('other.ecr');
anim.destroy();
```

- Один `requestAnimationFrame` на страницу. Анимации за экраном и в фоновой вкладке не считаются.
- У всех анимаций страницы общий бюджет времени на кадр экрана: 7 мс, пока страницу листают 3 мс. Кто не уложился,
  рисуется в следующий кадр, поэтому страница не подвисает. Меняется через `ECore.setBudget(мс, мсПриПрокрутке)`.
- Кадр файла рисуется один раз, даже если экран обновляется чаще (120 Гц). Рисовать и между кадрами: `subframe: true`.
- Одновременно играет не больше `ECore.setMaxLive(n)` анимаций (на телефоне 6, на компьютере 16), остальные ждут очереди.
- Если WebGL программный или кадр через него выходит дольше 12 мс, плеер остаётся на Canvas 2D.
- Первые кадры плеер сверяет с тем же кадром, посчитанным на процессоре: сравнивается то, что с видеокарты реально попадает
  на холст страницы. При расхождении он пишет в консоль, что и где не сошлось, и дальше рисует через Canvas 2D.
  Узнать результат: `ECore.glFault()` (пустая строка, если всё верно). Выключить сверку: `ECore.setVerify(false)`.
- Когда анимаций на экране больше, чем разрешено играть разом, доигравшая круг уступает место ждущей: играют все по очереди.
- `destroy()` отпускает наблюдателей и холст. Тег `<e-core>` делает это сам, когда его убирают со страницы.

### Готовый tgs в .ecr

```
node bin/ecore.js import sticker.tgs -o sticker.ecr
```

### Свой стикер из исходника

```
node bin/ecore.js build examples/nick.svg --set name=привет    # получится nick.ecr и nick.tgs
```

То же в браузере: подключить `ecore-compiler.js` (это `ecr.js` и `source.js` подряд) и вызвать
`ECore.build(текст, { fonts: { имя: ArrayBuffer }, slots: { имя: 'текст' } })`. Вернётся `{ ecr, lottie, warnings, slots }`.

### На сервере и в боте

```js
const { renderRGBA } = require('./src/ecore.js');
const img = renderRGBA(fs.readFileSync('sticker.ecr'), 0, 512);   // { width, height, data }: RGBA, альфа не умножена
```

Или сразу в PNG: `node bin/ecore.js frame sticker.tgs --frame 40 --size 512 -o кадр.png`.
Браузер, холст и rlottie для этого не нужны.

## Правка без пересборки

Для редакторов: сцена строится прямо из документа Lottie, дальше любую деталь можно менять на лету.

```js
const scene = ECore.fromLottie(json);                  // нужен ecr.js рядом
const anim = ECore.mount(canvas, scene);
const hit = anim.pick(event.clientX, event.clientY);   // что под курсором: { src, layer, name }
anim.patch(hit.src, { color: '#ff3b30' });             // перекрасить заливку или обводку, даже градиентную
anim.patch(hit.layer, { x: 12, y: -4 });               // сдвинуть слой или группу в единицах сцены
anim.patch(hit.src, null);                             // вернуть как было
anim.bounds((style) => style.layer.src === hit.layer); // рамка для выделения, в координатах экрана
```

`src` это путь узла в исходном документе (`layers/3`, `layers/3/shapes/0/it`, `layers/3/shapes/0/it/2`),
поэтому редактор знает, какой узел JSON менять, когда правку надо записать.

В своих исходниках элементам дают имена, и тогда хватает имени: `anim.names()`, `anim.set('heart', { color, x, y })`,
`anim.reset('heart')`. Подробнее в разделе «Слои, цвета и перенос» в [SPEC.md](SPEC.md).

## Командная строка

```
node bin/ecore.js build  исходник.svg [-o папка] [--set слот=текст] [--still]   исходник -> .ecr и .tgs
node bin/ecore.js import файл.tgs [-o файл.ecr] [--still]                       готовый tgs -> .ecr
node bin/ecore.js frame  файл.ecr|.tgs|.svg [-o кадр.png] [--frame 0] [--size 512]   кадр своим ядром
node bin/ecore.js render файл.svg|файл.tgs [-o лист.png] [--frames 0,45,90]     лист кадров через rlottie: так покажет Telegram
node bin/ecore.js info   файл.ecr
node bin/ecore.js serve  [порт]                                                 страница-пример из dist/
```

Собрать страницу-пример: `node tools/build-site.js`, затем `node bin/ecore.js serve 8080`.
Если положить свои `.tgs` в папку `gifts/`, на странице появится раздел «готовые tgs тоже играет».

## Как устроен файл .ecr

`ECR2`, байт флагов, дальше тело, сжатое своим deflate. В теле:

- структура сцены: композиции, слои, группы, стили. Ключи записаны номерами из общей таблицы, числа varint;
- числа анимации: ключи одной дорожки лежат разницей к предыдущему ключу, координаты с шагом 1/64, цвета и easing 1/1024.

Вложенная композиция хранится один раз, сколько бы раз её ни вставили. Эллипсы и прямоугольники лежат параметрами,
движение по кривой лежит касательными, а не запечённой дорожкой.

## Совпадение с Telegram

Ядро рисует так, как рисует rlottie в Telegram, включая его особенности. Все они сняты опытами и подписаны в коде:

- у вложенной композиции с несколькими слоями прозрачность применяется ко всей группе, у слоя-шейпа к каждой заливке;
- вложенная композиция обрезается своей рамкой; если рамки вложенных композиций не пересекаются, обрезка снимается;
- маска-matte берётся со слоя, который лежит прямо над слоем с `tt`;
- easing один на все измерения, альфа цвета не читается, перекос (skew), merge paths, эффекты и режимы наложения не рисуются;
- стопы прозрачности градиента сводятся со стопами цвета по правилу rlottie;
- длина для trim, пунктира и движения по кривой считается его приближённой формулой, время слоёв округляется до целых кадров;
- слой, у которого `ks` записан массивом, обрывает разбор: Telegram покажет только слои до него.

## Проверки

```
node tools/conform.js папка/с/tgs 128                            # ядро против rlottie без браузера, сотни файлов за раз
node tools/animtest.js                                           # цикл кадров, очередь, бюджет, правки на лету (без браузера)
node tools/check.js  examples/nick.svg,sticker.tgs 256           # плеер в браузере против rlottie, BACKEND=gl|2d|soft, QUICK=1
node tools/native.js examples/nick.svg 256                       # компилятор против самого браузера
node tools/bench.js  examples/nick.svg,sticker.tgs 256           # мс на кадр с синхронизацией GPU, BACKEND=gl|2d
node tools/selftest.js examples/heart.svg                        # перекраска и перенос через set() совпадают с исходником
node tools/pagetest.js http://127.0.0.1:8080/ --gl               # страница в браузере: элементы, цвет, перенос, плавность
```

`conform.js` главный: eCore рисует кадр на процессоре, rlottie рисует тот же кадр, считается PSNR.
`DUMP=8` сохраняет картинки худших файлов в `build/conform`: слева rlottie, в середине eCore, справа разница.

Остальные, кроме `animtest.js`, запускают headless Chromium (`CHROME`, `CHROME_LIBS`), `selftest` и `pagetest` ещё требуют
`playwright-core` (`PLAYWRIGHT=путь`). При малом запасе памяти браузеру дают свои флаги: `CHROME_ARGS="--disable-gpu"`.

## Что внутри

```
src/ecore.js     плеер: движок, три способа рисования, общий цикл, тег <e-core>, свой inflate
src/ecr.js       сцена -> .ecr, свой deflate
src/source.js    исходник -> сцена: разбор SVG и CSS, шрифт TrueType с кернингом, текст в кривые
bin/ecore.js     командная строка
tools/           проверки и сборка страницы-примера
examples/        четыре исходника
site/            страница-пример, tools/build-site.js собирает её в dist/
fonts/ vendor/   чужие файлы для страницы и проверок, см. THIRD_PARTY.md
```

## Чего ядро не умеет

- Маски слоя (`masksProperties`), повторитель (`rp`), звезда (`sr`) и time remap не рисуются.
  `import` и `conform` называют такие файлы.
- Маска по яркости (`tt` 3 и 4) написана, но с rlottie не сверена: проверить было не на чем.
- Плеер есть для браузера и Node. Версий под iOS и Android нет, поэтому заменить движок внутри приложений Telegram он не может.
- Скорость на телефонах и настоящих видеокартах не измерена.
- Исходник: список ограничений в конце [SPEC.md](SPEC.md).
