# Исходник eCore, версия 0

Исходник это обычный файл SVG с CSS-анимацией. Он открывается в браузере и в Figma, а компилятор
делает из него `.ecr` для плеера и `.tgs` для Telegram. Текст в исходнике остаётся текстом.

Компилятор понимает подмножество SVG и CSS. Всё, что в него входит, работает как в браузере:
это проверяется сверкой с Chromium (`tools/native.js`). Этот файл целиком можно дать ИИ как правила.

## Каркас

```xml
<svg xmlns="http://www.w3.org/2000/svg" viewBox="0 0 512 512" data-duration="3s">
  <style>
    .c { transform-box: fill-box; transform-origin: center; }
    #star { animation: spin 3s linear infinite; }
    @keyframes spin { to { rotate: 72deg; } }
  </style>
  <polygon id="star" class="c" fill="#FFD23F" points="..."/>
  <text data-slot="name" x="256" y="300" text-anchor="middle" font-family="Seymour One" font-size="96" fill="#fff">swex</text>
</svg>
```

- `viewBox`: размер холста. `data-duration`: длина цикла. `data-fps`: частота, по умолчанию 60.
- Для Telegram: холст 512×512, цикл до 3 секунд, 30 или 60 кадров в секунду, файл до 64 КБ.

## Что можно рисовать

- Фигуры: `path` (все команды), `rect` (с `rx`, `ry`), `circle`, `ellipse`, `line`, `polyline`, `polygon`.
- Группы `g`, повтор `use href="#id"`, заготовки в `defs`.
- Заливка и обводка: `fill`, `stroke`, `stroke-width`, `fill-opacity`, `stroke-opacity`, `opacity`, `fill-rule`.
- Цвета: `#rgb`, `#rrggbb`, `#rrggbbaa`, `rgb()`, `rgba()`, `hsl()`, имена, `none`.
- Градиенты: `linearGradient` и `radialGradient` со `stop`, `gradientUnits`, `gradientTransform`.
- `paint-order="stroke"` кладёт обводку под заливку: так делается контур у текста.
- Концы и стыки обводки всегда круглые.

Стили задаются атрибутами, атрибутом `style` или в `<style>`. Селекторы: `#id`, `.класс`, `тег`, `тег.класс`.

## Движение

Движение описывает CSS: `@keyframes` и `animation`.

- В `animation` работают имя, длительность, кривая, задержка, число повторов (`infinite`),
  направление (`alternate`, `reverse`), `fill-mode` (`both`, `forwards`, `backwards`). Несколько анимаций пишутся через запятую.
- Кривые: `linear`, `ease`, `ease-in`, `ease-out`, `ease-in-out`, `cubic-bezier(...)`, `steps(...)`.
- В ключах можно менять: `transform`, `translate`, `rotate`, `scale`, `opacity`, `fill`, `stroke`, `stroke-width`, `stroke-dashoffset`.
- В `transform` функции идут в порядке translate, rotate, scale. Другой порядок делается вложенной группой.

## Четыре правила, на которых чаще всего ошибаются

1. **Центр.** По умолчанию элемент вращается и растёт вокруг точки 0 0 холста. Чтобы вокруг своего центра, дайте ему
   `transform-box: fill-box; transform-origin: center`. Компилятор об этом предупреждает.
2. **Место отдельно, движение отдельно.** Если элемент стоит на месте через атрибут `transform`, а на нём же анимация
   `scale` или `rotate`, он уедет. Место задаёт обёртка: `<g transform="translate(100 80)"><path class="c" .../></g>`.
3. **Цикл без шва.** Берите `infinite` и длительность, на которую делится `data-duration`. Сдвиг по фазе делается
   отрицательной задержкой: `animation-delay: -0.5s`.
4. **Появление.** Чтобы элемент не мелькнул до старта и остался после конца, пишите `both`:
   `animation: pop 0.5s ease-out 0.3s both`.

## Линия, которая рисуется сама

```xml
<path d="..." pathLength="1" stroke-dasharray="1" fill="none" stroke="#FFD23F" stroke-width="18"/>
```
```css
#line { animation: draw 0.5s ease-out both; }
@keyframes draw { from { stroke-dashoffset: 1; } to { stroke-dashoffset: 0; } }
```

Бегущая дуга: `stroke-dasharray="0.25 0.75"` (штрих и пробел в сумме равны длине пути) и `stroke-dashoffset` от 0 до -1.

## Текст

```xml
<text data-slot="name" data-fit="400" x="256" y="300" text-anchor="middle"
      font-family="Seymour One" font-size="96" fill="#fff"
      stroke="#24105E" stroke-width="16" paint-order="stroke">swex</text>
```

- Понимает `x`, `y`, `font-family`, `font-size`, `text-anchor`, `dominant-baseline`, `letter-spacing`. Кернинг берётся из шрифта.
- Шрифты лежат в `fonts/`: Seymour One и Montserrat (жирный). Оба с кириллицей. Свой шрифт: положить `.ttf` в эту папку.
- `data-slot="имя"`: текст можно заменить при сборке, `ecore build файл.svg --set имя=ecronx`.
- `data-fit="400"`: если текст шире 400, он ужимается вместе с обводкой.
- `data-letters="wave 0.75s ease-in-out infinite alternate"` и `data-stagger="0.06s"`: анимация применяется
  к каждой букве со сдвигом. Отрицательный шаг даёт волну без шва.

Слот, вписывание и побуквенное движение это добавки eCore, браузер их не знает и покажет текст неподвижным.

## Слои, цвета и перенос без пересборки

Каждый элемент с `id` в исходнике это **именованный слой**. Имя слоя = его `id`. Без `id` имя берётся из тега
(`polygon`, `path`), и таких имён несколько, поэтому давайте `id` всему, чем собираетесь управлять.
Группа `<g id="...">` тоже слой: всё, что внутри неё, едет вместе с ней.

Плеер после загрузки знает список слоёв и отдаёт его через `names()`:

```js
anim.names();
// [{ name: 'burst', move: true, paint: true, color: '#ffd23f' }, { name: 's1', move: true, paint: true, color: '#ffffff' }, ...]
// move: слой можно сдвинуть; paint: у слоя есть сплошная заливка или обводка, её можно перекрасить;
// color: цвет из исходника (null, если цвет анимирован в CSS)
```

Менять можно без пересборки, с того же кадра:

```js
anim.set('burst', { color: '#ff3b30' });  // перекраска: все сплошные заливки и обводки слоя
anim.set('burst', { x: 40, y: -20 });     // сдвиг в единицах viewBox, абсолютный (не прибавляется к прошлому)
anim.reset('burst');                      // вернуть цвет и положение из исходника
```

Правила, которые стоит знать:
- Сдвиг двигает слой целиком, вместе с его собственной анимацией (поворотом, пульсом) и вложенными слоями.
  Перекраска заменяет и цвет из исходника, и цвет, анимированный в CSS.
- Градиенты не перекрашиваются через `set`: у слоя с градиентом `color` будет `null` или цвет его сплошных частей.
- `set` меняет только позицию и цвет. Размер и поворот слоя задаются анимацией в исходнике.
- Стартовые значения можно записать прямо в файл, тогда сцена открывается уже в нужном виде и скачивается так же:

```js
ECore.build(svgText, { over: { burst: { x: 40, y: -20, color: '#ff3b30' } } });   // .ecr с этими значениями
```

Порядок работы для цветной анимации (так её проверяем):
1. Пишем исходник: фигуры с `id`, движение в CSS (`@keyframes`), текст через `<text data-slot>`.
2. Смотрим список слоёв через `names()`, чтобы имена совпали с тем, что будет в коде.
3. Меняем цвет и положение через `set`, а не через пересборку исходника: так быстрее и без скачков.
4. Проверяем картинку по кадрам: `node bin/ecore.js render`. Анимацию, которой не видно в кадрах, не оставляем.

## Чего нет в версии 0

Маски и `clipPath`, фильтры (тень, размытие), картинки, пунктир, морфинг пути, `tspan`, SMIL (`<animate>`),
селекторы с пробелом, перекос у движущихся элементов. Прозрачность группы умножается на каждого потомка,
а не накладывается на группу целиком: у полупрозрачной группы с перекрытиями видно нижние слои.

## Как проверять

```
node bin/ecore.js render файл.svg -o лист.png --frames 0,45,90,135
```

Команда рисует выбранные кадры в одну картинку тем же движком, что в Telegram. ИИ без этого шага красиво
не сделает: написал, отрисовал, посмотрел, поправил. Ошибки в исходнике компилятор называет с номером строки.
